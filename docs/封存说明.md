## 一、封存原因

**没有业务主体。**

本项目的需求来自一家海外工商业储能（C&I ESS）出口企业，但**该公司未实际接入**：

- 无产品认证文件、合规文件、技术白皮书原件 → **产出不了可信的对外内容**
  （违反不了 `系统总纲.md` §8 红线 1：技术/合规表述必须可溯源到公司事实卡）
- 无发布渠道与效果回流 → **L1 做完也无法验证价值**
- 无 CRM / 阿里国际站 / 社媒后台权限 → L2 不可推进

**关键区分**：不是"数据拿不到"，是"**没有业务主体，系统无法被验证**"。

> 不能自证的系统，停在骨架是对的。
> （对照：`ai-delivery-harness-engineering` 能自证——`make gate` 全绿；本项目不能。）

## 五、复活条件

**满足全部三条才重启：**

1. 获得**真实业务方接入**（提供认证文件 / 产品素材 / 发布渠道，三者至少其一）
2. 明确**北极星指标**（`系统总纲.md` §10 待确认项：当前最痛是"线索量"还是"转化率"）
3. 至少一个闭环的**效果回流通道**可用（能拿到数据证明它产生了业务价值）

**条件未满足时，本项目不进入开发。**

## 六、它证明什么

本项目是**唯一一个从真实企业需求出发**的项目。

它证明的**不是**"我做完了一个系统"，而是"**我能把一句业务需求翻译成可执行的系统设计**"：

```
业务原话 → 需求基线 → 系统总纲 → 闭环拆分(L1–L5)
        → 三大资产模型 → 五条横切红线 → P0–P3 路线图 → spec/plan
```

**即使未完成，这个证据依然成立。**
