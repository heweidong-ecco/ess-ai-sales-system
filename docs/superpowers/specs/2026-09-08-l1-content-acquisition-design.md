## 1. 背景与目标

公司靠 AI 内容 SOP 把"内容产能"从瓶颈变成增长杠杆:B2B、大客单、强技术售前,买家(储能集成商/EPC/业主)决策看技术可信度,内容需要专业、多语言、持续供给。

**本闭环要跑通的业务结果**:内容产能显著提升且不靠加人 → 各渠道稳定获客 → 询盘能被归因到内容 → 反哺选题 → 形成可迭代的内容飞轮。

**挂的指标**(总纲 §2):内容产量 / SEO 覆盖 / 触达;内容归因询盘数。

## 2. 范围

**做(L1.1 MVP):**
1. **事实资产层**:把现有产品/技术资料结构化为一组可引用的「事实卡片」(Facts) + 多语言术语表
2. **内容生产 SOP**:从选题卡 → 事实引用 → 分渠道模板 → 多语言成稿的标准化工作流(AI 生成 + 人审)
3. **四种渠道产物**:SEO 博客 / LinkedIn 帖子 / 阿里国际站多语言详情页文案 / 短视频脚本
4. **人审发布工作台(轻量)**:一页看板/清单,状态流 = 草稿 → 审校 → 待发 → 已发
5. **回流登记(轻量)**:每篇内容上线后登记渠道表现(曝光/点击/带来的询盘),月度复盘反哺选题
6. 仓库内目录约定 + 模板库(可被 Claude Code / AI 工具直接调用)

**不做(明确排除,防蔓延):**
- 自动发布 / 全渠道 API 集成(下一步增量,见 §9)
- 与 L3 评分/画像深度集成(询盘只做归因标记,不做评分)
- L4 客服/知识库问答系统(独立闭环)
- 视频成片生成(只产出脚本)
- 全语言铺开(首期 EN + DE)

## 4. 角色

- **业务负责人(审校者)**:把关技术事实与措辞;唯一能"放行发布"的人
- **内容执行者(AI + 你)**:按 SOP 产出草稿、做事实引用、多语言、SEO
- **销售(回流消费者)**:提供一线客户提问 → 变成选题;消费"已发内容库"复用给客户

## 5. 架构与组件

```
   素材(中文/英文 PDF·文档·图片)
        │  (C1) 卡片化
        ▼
   ┌─────────────────────────────────────────────┐
   │  事实资产层  Facts + 术语表(唯一事实源)        │
   └───────────────┬─────────────────────────────┘
                   │ 引用/校验
   ┌───────────────▼─────────────────────────────┐
   │  内容生产 SOP  C2                             │
   │  选题卡 → 大纲 → 分渠道模板 → EN/DE 成稿      │
   │  (博客/LinkedIn/阿里详情页/短视频脚本)         │
   └───────────────┬─────────────────────────────┘
                   ▼
   ┌───────────────┴─────────────────────────────┐
   │  C3 人审发布台   草稿→审校→待发→已发          │
   └───────────────┬─────────────────────────────┘
                   ▼
   ┌───────────────┴─────────────────────────────┐
   │  C4 回流登记   渠道表现 + 内容归因询盘         │
   │  月度复盘 → 反哺选题                          │
   └─────────────────────────────────────────────┘
```

**C1 事实资产层(Facts)**
- 单元:一条事实卡片 = `编号 / 主题 / 事实内容(双语) / 来源文档 / 适用市场 / 最后核验`
- 类别:产品参数、技术优势、合规认证、项目案例、公司资质、报价政策(如有)
- 作用:AI 写作时"只准引用 Facts,不得自创技术表述"——红线1 的实现载体

**C2 内容生产 SOP**
- 输入:选题卡(目标买家人设 + 市场 + 意图 + 关键词)
- 步骤:选题 → 拉取相关 Facts → 分渠道模板 → 成稿(EN 为主稿)→ 译制 DE(人工终校)
- 模板:博客(结构:问题/方案/事实/CTA)、LinkedIn(专业短帖)、阿里详情页、短视频脚本(口播+画面建议)
- SEO:关键词表(如 "commercial & industrial battery storage / BESS Germany / C&I ESS")驱动标题与结构;禁止关键词堆砌

**C3 人审发布台**
- 形态:仓库内 `pipeline/` 下每篇一个文件夹 + 一张总看板(README/表格)
- 状态流转与发布 checklist;发布后把"链接 + 表现登记表"归档

**C4 回流登记**
- 每周 10 分钟登记:渠道 / 曝光 / 点击 / 带来询盘(是否可归因)
- 月度输出:哪类选题 → 哪些内容带来询盘 → 下月选题建议(反哺 C2)

## 6. 仓库目录约定(初拟)

```
content/
  facts/            # 事实卡片(双语 Markdown)
  glossary/         # 术语表 EN↔DE↔中文
  keywords/         # SEO 关键词表
  pipeline/         # 每篇内容一个文件夹:选题卡/草稿/终稿/发布记录
    <topic-slug>/
      brief.md      # 选题卡
      draft.en.md   # 主稿
      draft.de.md   # 译稿
      variants/     # linkedin/blog/ali-detail/video-script 产物
      publish-log.md
  tracker.md        # 人审/发布看板(轻量)
  monthly-review/   # 月度回流复盘
sop/                # SOP 说明 + 模板 + AI 提示词(可执行)
```

## 7. AI 使用红线(进每个 SOP)

1. 技术表述只准引用 Facts,禁止自创;新事实未入 Facts 前不得进正文
2. 多语言译制必须保留关键术语一致性(查术语表)+ 人工终校
3. 一切对外内容经人审放行后才能发布(红线3)
4. SEO 合规:写给人读优先,不堆砌、不欺骗
5. 每条内容关联来源,便于回查(可溯源)

## 8. 指标与验收(L1.1 完成判定)

- [ ] 事实卡片库 ≥ 30 张,覆盖在售主力产品 + 主要认证
- [ ] 4 类渠道模板 + SOP 文档可用,AI 能按 SOP 独立产出合格草稿
- [ ] 产能:4 周内稳定 ≥ 8 篇/周(博客+LinkedIn+详情页/脚本),不增加审校人力
- [ ] 发布与回流登记跑通 1 个完整月度复盘
- [ ] 至少 1 个询盘可归因到内容(链路验证)

## 9. 后续增量(不在本 spec)

- 接入渠道 API 自动发布(LinkedIn 等)
- 回流数据自动采集,连接 L3 评分
- 语言二期(西/荷/法/阿)
- 与销售一线需求打通选题来源(知识库体系,衔接 L4)

## 10. 开放问题(不阻塞开工)

- 公司是否有独立站/博客平台(A5,先按"有"预留)
- 主力在售产品线与认证清单(卡片化首批对象,开工第一步盘点)
- 业务负责人是否单人审(影响吞吐,先按单人设计)
