## 背景

项目取向(DEC-001 + CLAUDE.md)为"优先 Claude Code + 轻量方案跑通,不预设重型平台"。G3 把选型按层落成表,让各闭环 spec 直接取用;依赖 G1 未知项(O1~O6)的选型以"缺省 + 触发规则"挂起,到位再定。

## 裁定

### S1 · 现选(直接取用)

| 项 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Claude Code + superpowers**(已装,project 作用域) | 唯一模型运行时;spec/plan/决策都靠它执行,无需独立网关 |
| 资产载体 | **git + Markdown(双语)/CSV/JSON** | 文本可人审、git 可 diff/审计/回滚;见 DEC-003 C1 |
| 状态/编排载体 | **仓库 tracker 表格 + pipeline 目录**;触发默认人起头 | 轻量看板即可承载人审 gate;无人值守需求前不跑服务 |
| 内容生产/翻译 | Claude Code 模型能力 + `content/glossary` 术语表 + **人工终校**(红线3) | 多语言质量靠术语表+人审,不依赖单独翻译 API |
| 前检索 | **事实卡编号引用 + grep/结构化检索**(L4 前) | facts 有 schema、数量可控时无需向量库 |
| 凭证/密钥 | **永不入库**(.gitignore + 环境变量) | 渠道账号安全红线(红线4) |

### S2 · 缺省待定(挂起,到位即触发,不阻塞)

| 项 | 候选 | 依赖/触发 | 定夺点 |
|---|---|---|---|
| CRM/ERP 对接方式 | 官方 API > 导出 > 人工;统一"适配器"接口(导入/导出+凭证) | **G1-O1**(产品与 API),deadline L2.1 开工前 | L2.1 spec |
| 渠道账号/数据 API(L2 抓取 / L1 自动发布) | 官方 API / 导出 / 人工回流 | **G1-O2**(账号与能力),deadline G2 前 | G2 数据源清单 |
| 资产层升级 SQLite | SQLite(单文件、零运维) | 事实卡/线索 > ~500 或需联表/权限查询 | 对应闭环 spec(DEC-003 C2) |
| 向量库 / RAG | 候选:sqlite-vec / LanceDB / pgvector(按部署环境再评) | L4 开工且知识资产需语义召回 | **L4 spec**(DEC-003 C2,现不引入) |
| 最小调度 | cron / GitHub Actions / Claude Code schedule | L2.2 起需无人值守/定时/外部 API 拉取 | L2.2 spec |
| 薄界面(角色自取数据) | 静态导出 / 仓库页面 | 出现非 Claude Code 用户需自取数据/操作 | 对应闭环 spec |

### S3 · 明确不选(现在,含理由)

| 项 | 理由 |
|---|---|
| 自建/深度自研 CRM | 现成 CRM 待确认(G1-O1);自建反悔成本极高,违背轻量取向 |
| 消息中间件 / 队列 | 无跨服务异步场景;单一仓库内不需要 |
| 复杂 workflow 引擎(n8n 等) | DEC-001 明确不上重型编排;流程用 SOP + tracker 已可承载 |
| 独立 LLM 网关 / Agent 编排框架 | Claude Code 即运行时,额外网关是重复建设 |
| 重型 BI / 数据平台 | L3 前无此数据规模;先仓库 CSV 回流 |

> 更新纪律(DEC-002):任一"待定→定夺"落地为事实后,回本表 + 对应 spec 对齐,不静默改。每项升级仍走 DEC-003 C5 的独立 DEC 流程。
